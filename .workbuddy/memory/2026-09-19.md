### 关键设计决策与踩坑

- **索引即事实**：脚本用 `git ls-files -s` 读索引 + `git cat-file blob <sha>` 读内容，而非直接读磁盘文件。
  这样换行符规范化行为与 `git push` 完全一致，规避 Windows 下 LF→CRLF 警告带来的差异。
- **对比方式**：用 API 拉远程 tree（`?recursive=1`）与本地索引的 (mode, blob_sha) 逐条比对，
  而不是依赖本地 `origin/main` 引用——因为该引用本身可能卡在旧值（见下）。
- **删除项**：tree entry 的 `sha` 置 `null` 即可删除。
- **ref 更新用 `force=false`**，保证快进，避免覆盖他人提交；失败则让用户重跑（会基于新 HEAD 重建）。
- **本地对齐**：API commit 与本地 commit SHA 不同属预期，脚本自动 `reset --hard` 对齐并提供 `--no-sync` 逃逸。
- 已知环境事实：`gh` CLI **未安装**，凭据在 Windows 凭据管理器（username=tuoqi-stats），
  `git credential fill` 可取到。设计时不要依赖 gh。
- 本仓库 `.workbuddy/memory/` 与 `.workbuddy/skills/` **是 git 跟踪的**共享产物，正常提交，不当作本地缓存忽略。
