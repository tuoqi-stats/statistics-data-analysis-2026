### 关键经验

1. **先做连通性预检再决定路线**：`timeout 30 git ls-remote origin HEAD` 有输出就走标准 `git push`，别默认走 API。
   本次 `ls-remote` 和 `push` 都一次通过 —— 网络"时好时坏"意味着**不能因为历史上失败过就预先降级**。
2. **推送成功 ≠ 引用写对**：本次 `git push` 输出正常（`e1cde3a..85dc584 main -> main`），但
   `git status -sb` 显示 `## main...origin/main [gone]`、`git rev-parse origin/main` 报 `unknown revision`。
   **这是本机老毛病，不是推送失败，不要重复推送。**
3. **引用修复的新现场**：本次 `.git/refs/remotes/origin/` 和 `.git/packed-refs` **两者都不存在**。
   直接 `mkdir -p` + `printf SHA > .git/refs/remotes/origin/main` 即可 —— 这次 loose ref **成功留住**了
   （历史上曾出现写不住、必须改 packed-refs 的情况）。修好后 `git status -sb` 显示干净的 `## main...origin/main`。
4. **中文路径提交正常**：57 个含中文名的文件（`python-basics/01_变量/` 等）add/commit/push 全程无问题，
   `core.autocrlf=true` 下 CRLF→LF 的 warning 属正常，不影响结果。
5. **`git add` 用精确路径**（`git add python-basics/ 02.py <memory文件>`）而非 `-A`，隔离可能的并发改动。
