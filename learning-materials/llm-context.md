# 大模型上下文（LLM Context）

> 生成日期：2026-09-09 ｜ 类别：AI 概念学习资料

（注：本文指大语言模型单次推理时可见的信息窗口及其组织管理机制——含上下文窗口、上下文构建与上下文工程（Context Engineering）；不指编程中的"执行上下文"（execution context）或数据库语境下的同名概念。）

## 1. 概念个人解释

先打个比方：大模型像一位博览群书的专家，却没有长期记忆——每次对话都相当于把他叫进一间办公室，你能给他的全部信息，只能摆在办公桌这一块台面上：公司规章（系统提示）、之前聊过的便签（对话历史）、刚查到的资料（检索结果）、他此刻要回答的问题。桌面尺寸是有限的，这就是大模型上下文（Context）。

正式一点说：上下文是模型单次推理时可见的完整输入序列，以 token 为计量单位；其容量上限称为上下文窗口（Context Window）。"大模型上下文"在实践中通常涵盖三层意思：一是容量（窗口有多大），二是拼装（系统提示、对话历史、检索内容如何组织进窗口），三是工程（即上下文工程——如何在有限窗口内为模型提供"恰好够用"的信息，而不是能塞多少塞多少）。

## 2. 核心机制或组成

大模型上下文的运作可以拆成四个关键要素：

1. **窗口与 token 计量**：上下文以 token 计（中文约 1 个汉字折合 1-2 个 token，英文约 4 个字符折合 1 个 token），且输入与输出共享同一预算。量级演进：早期模型 2K-4K，如今主流 128K 到 1M（Claude 200K/1M、Gemini 最高 2M）。
2. **上下文的四类组成**（一次推理的完整拼装）：
   - 系统提示词（system prompt）：角色设定、规则、工具定义
   - 对话历史（chat history）：多轮消息
   - 检索与工具结果：RAG 片段、工具返回值、文件内容
   - 用户当前输入

   组织顺序会真实影响效果——模型对开头与结尾的信息利用率高，中部偏低（即 lost in the middle 现象）。
3. **窗口管理三板斧**（超出窗口时）：
   - 截断/滑动窗口：丢弃最旧消息
   - 压缩摘要：把长历史摘要成短文再入窗
   - 外部记忆（memory）：把信息外置存储、按需检索注入——用"检索"换"窗口"
4. **上下文工程（Context Engineering）**：为每次推理动态构建"恰好够用"的信息。信息并非越多越好——长上下文带来噪声、干扰与成本。它与 Agent Skill 的渐进式披露（progressive disclosure）一脉相承：SKILL.md 分层加载"名称简介 → 全文 → 附录"，本质上就是在管理这个窗口。

## 3. 具体应用场景

1. **长文档全文分析**：借助 200K-2M 级窗口，把整本书、整个代码库直接塞进窗口做全文问答（替代部分传统分块 RAG 场景）；各家以"大海捞针"（needle in a haystack）测试检验超长窗口的召回能力。
2. **编程智能体的上下文管理**：Claude Code、Codex 等工具自动将相关文件、代码库地图、会话历史拼装进窗口，并在接近上限时自动压缩摘要，支撑数小时的长任务——Anthropic 的上下文工程博客正是以这类 agent 为范例。
3. **RAG 应用中的上下文设计**：企业知识库场景下，检索多少条、怎么排序、放在窗口什么位置，直接影响回答质量；实践中优化上下文组织常常比换更大的模型更划算。
4. **对话产品的跨会话记忆**：ChatGPT Memory、Claude 的项目知识等功能的本质，是把超出单次窗口的历史外置存储，跨会话按需注入窗口——用"外部记忆"突破"工作记忆"的限制。

## 4. 容易混淆的问题或使用边界

1. **上下文窗口 vs 训练数据**：训练数据是"写进模型权重里的知识"（模型学过什么），上下文是"本次推理时摆在桌面上的纸条"（模型此刻能看到什么）。模型不知道你公司昨晚的会议内容——除非你把它放进上下文。
2. **上下文窗口 vs 向量数据库/RAG**：窗口是容量有限的"工作记忆"，向量库是容量近乎无限的"外部仓库 + 检索员"。大窗口时代二者互补而非替代：全部塞进窗口有成本与噪声代价，检索式注入仍是主流做法。
3. **"窗口大" vs "用得好"**：标称 1M 窗口不等于全程高利用率——中部内容召回衰减（lost in the middle）、指令遵循率随长度下降、成本随 token 数线性上升。工程上"少而准"常胜过"多而全"，这正是上下文工程的核心主张。
4. **使用边界与注意**：长输入按 token 计费，成本随长度线性增长；需要模型精确遵循的指令应放在开头或结尾；跨会话信息必须走外部记忆机制，不能指望模型"记得"上一场对话；任务对实时性敏感的内容要靠工具调用注入，而非预先塞满窗口。
