大模型的上下文（Context）

1个人通俗解释

上下文 = AI的办公桌桌面 大模型本身没有记忆，只能看见桌面上摆放的内容：任务指令、聊天历史、参考资料。 1.桌面大小有限（上下文窗口），内容太多就要丢弃旧内容或压缩； 2.桌面首尾内容看得清楚，中间内容容易被遗忘； 3.新开会话，桌面全部清空，不会保存旧对话。 AI没有抽屉柜子，跨会话记忆，需要外部存储重新放到桌面上。

2核心机制

2.1 上下文是怎么拼出来的

一次请求的上下文通常按这个顺序拼接，模型对每一部分一视同仁地"看到"：

上下文 = 系统提示(System Prompt)
        + 示例(Few-shot 示例)
        + 对话历史(历史轮次)
        + 检索/参考资料(RAG 注入)
        + 当前用户输入
// 全部切分成 token，送入 Transformer，靠 self-attention 建立彼此关联

2.2 Token 与上下文窗口

  • 分词（Tokenization）：文本先被切成 token（不等于字/词，一个中文字常是 1–2 token）。上下文长度以 token 计。
  • 上下文窗口（Context Window）：模型一次能处理的最大 token 数。早期 GPT-3 是 2K，现在主流模型普遍到 128K–1M。
  • 窗口满 = 遗忘：超出窗口时，系统一般从最早的历史开始截断（滑动窗口），所以"太久以前的对话"会被丢弃。

2.3 注意力如何"用"上下文

Transformer 用 self-attention（自注意力）让每个 token 都能"关注"上下文里所有其他 token，从而决定每个词的语义权重。核心公式：

Attention(Q, K, V) = softmax(QKT / √dk) · V
// Q=查询 K=键 V=值；√d_k 缩放防止点积过大导致梯度消失
// 关键：注意力对全部上下文是 O(n²) 复杂度 → 上下文越长，计算量/显存增长越快

2.4 成本与延迟

上下文越长，输入 token 费用更高、首字延迟更大（attention 是 n² 增长）。所以"塞越多越好"并不成立——存在"中间迷失"现象：长上下文中段的关键信息反而更容易被忽略。

3真实应用场景

场景用在什么产品/环节为什么用上下文角色
长文档问答把整份 PDF/财报放进上下文直接提问（Gemini、Kimi 长文本）模型需"看见"全文细节才能精准回答，长窗口避免分块丢失全局信息核心机制
多轮对话ChatGPT、客服机器人保持上下文连贯后续回答要参考前面说过的话，全靠上下文携带历史核心机制
代码编辑Cursor/Claude Code 把相关文件塞进上下文再改代码改代码需看见函数定义、调用关系，靠上下文携带代码上下文辅助组件
检索增强(RAG)把检索到的知识库片段注入上下文再回答模型知识有截止日期，靠上下文注入"最新/私有"事实辅助组件
少样本学习在提示里给几个示例让模型模仿格式/风格不更新权重，仅靠上下文里的示例"现场学会"任务核心机制

共性：这些场景都靠"把信息摆进上下文"来让模型即时可用——窗口大小直接决定能处理任务的规模。

4易混淆边界

易混概念与本概念（上下文）的关键差异何时用哪个
长期记忆 (Memory)上下文是"本次请求能看见的文本"，用完即丢；记忆是跨请求持久化存储、按需检索回来的内容单轮内连贯用上下文；跨会话记住偏好用 Memory/向量库
训练数据 (Pretraining)训练数据在训练阶段固化进权重，回答时不可见；上下文是推理时实时注入的通用知识靠训练数据；本次任务的特定信息靠上下文
微调 (Fine-tuning)微调是改模型权重（永久改变行为）；上下文不改权重，只影响本次回答固定风格/领域习惯用微调；临时/动态信息用上下文
嵌入 (Embedding)嵌入是把文本变成向量用于检索；上下文是模型直接读的原始文本要"召回相关片段"用嵌入检索；要让模型"读到"用上下文

6自测思考题

  1. 复述：上下文窗口变大，为什么并不等于"模型变聪明了"？它和模型知识之间是什么关系？
    提示方向：区分"看见的信息"与"训练时记下的知识"。
  2. 机制题：按公式说明 self-attention 中 √dk 的作用，并解释为什么上下文越长计算成本增长越快。
    提示方向：点积缩放 + O(n²) 复杂度。
  3. 辨析题：用户问"模型到底记不记得我们上周聊的偏好？"——请从上下文与长期记忆的区别解释为什么默认"记不住"。
    提示方向：上下文用完即丢 vs 持久化记忆。
  4. 应用题：一份 200 页报告要问答，模型窗口只有 32K token 放不下。你会选 RAG 还是长上下文模型？各有什么取舍？
    提示方向：分块检索 vs 整体可见；精度 vs 全局信息。
  5. 迁移题：解释"Lost in the Middle"现象，并给一条提示词摆放策略来缓解它。
    提示方向：把关键信息放在开头/结尾，避免埋在中段。
