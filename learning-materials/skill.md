# Skill（技能）

> 生成日期：2026-09-09 ｜ 类别：AI 概念学习资料

（注：本文讲 "Skill" 作为 AI 与智能体领域的概念全景——技能的语义、两层谱系与产品形态。库内 [agent-skill.md](agent-skill.md) 讲的是其中主流机制（SKILL.md 能力包）的实现细节，两文互为补充：那篇讲"怎么运作"，这篇讲"是什么、从哪来、和什么相邻"。）

## 1. 概念个人解释

先从人的技能说起。你会骑自行车——平衡感早已长进了身体，说不出也忘不掉；你也会照着菜谱做一道从没做过的菜——通用能力（识字、切菜、控火）加上外部知识（菜谱）当场组合出技能；新员工入职照培训手册学会用公司系统——组织把"技能"写成文档传给每个人。AI 的技能恰好对应这三种形态。

放到 AI 语境下：Skill（技能）指智能体完成某类任务的成熟能力，当代语义分两层。**内隐技能**：训练写进模型权重的通用能力——写代码、翻译、推理，模型"会"但说不清、也改不动；**外显技能**：把"如何完成某类任务"的知识外化为可加载的指令包——模型"读了就会"，可读、可改、可分享。2025 年之后，"Skill" 在智能体产品语境中通常特指后者（即 Agent Skill，以 SKILL.md 文件为核心），本仓库正在使用的正是这一形态。

## 2. 核心机制或组成

一个当代智能体技能（外显层）的构成要素：

1. **触发描述（description）**：技能的"门牌"——一段简短的元数据，智能体据此判断"当前任务是否用得上这个技能"。写得含糊，技能就永远不会被想起。
2. **程序性知识（正文指令）**：技能的"干货"——步骤、规范、风格约束，用自然语言写成。这是技能区别于一般资料的关键：不是"关于某事的信息"，而是"怎么做成某事的操作方法"。
3. **配套资源（可选）**：脚本（把精确操作交给代码）、参考文档（细节分册）、模板资产（起点文件）。
4. **分层加载机制**：名称简介 → 全文 → 附录的渐进披露，控制技能数量增长时的上下文成本（详见 [agent-skill.md](agent-skill.md) 第 2 部分）。

两层谱系的获得方式对比——这是理解本概念的关键：

| | 内隐技能（权重内） | 外显技能（权重外） |
|---|---|---|
| 获得方式 | 大规模训练 | 写一个文件 |
| 生效方式 | 推理时自然流露 | 匹配任务时加载 |
| 修改成本 | 重新训练（百万美元级） | 编辑 Markdown（分钟级） |
| 可解释性 | 弱（黑箱） | 强（纯文本可读） |
| 通用性 | 强（跨任务） | 弱（限定任务域） |

## 3. 具体应用场景

1. **Anthropic Claude 平台**：2025 年 10 月起在 claude.ai、Claude Code、Agent SDK 中内置 Agent Skills——官方预装 PPT 生成、Word 处理、Excel 分析、PDF 处理等技能，并把"自定义技能"开放给所有用户，把个人工作流写成 SKILL.md 即可复用。
2. **WorkBuddy 智能体平台**：用户级（`~/.workbuddy/skills/`）与项目级（`.workbuddy/skills/`）双层技能体系加推荐市场；本仓库的 concept-material-generator 就是一个项目级技能实例（详见 [concept-material-generator.md](concept-material-generator.md)）。
3. **Claude Code 编程智能体**：开发者把团队代码规范、提交流程、部署手册写成技能与 slash command，让编程智能体按约定执行——技能成为"团队工程文化的可执行载体"。
4. **学术脉络（强化学习与机器人）**：技能学习（skill learning）、选项框架（options framework）、技能发现（skill discovery）研究如何把复杂任务分解为可复用子技能——与大模型的 SKILL.md 路线殊途同归：都在"把做成事的方法沉淀为可复用单元"，只是一个靠练出来，一个靠写出来。

## 4. 容易混淆的问题或使用边界

1. **Skill vs Tool（工具）**：工具是单件器械（一个 API、一个函数），技能是运用器械完成任务的成套方法。给智能体一份 API 文档（tool）不等于它知道何时调用、如何组合、出错怎么兜底（skill）——有锤子不等于会装修。
2. **Skill vs Agent Skill**：外延大小不同——Skill 是上位概念，涵盖从模型权重内的能力到 RL 技能学习的宽泛谱系；Agent Skill 是它在智能体产品中的具体机制实现（SKILL.md 格式、文件系统即接口）。类比：电子邮件 vs Gmail。
3. **Skill vs Plugin（插件）**：插件是封闭生态内的分发单元——需审核、需上架、依赖专用运行时（如 ChatGPT Plugins，2023 年上线、2024 年关闭的商店模式）；技能是开放文件——文件夹 + Markdown，无审核、无运行时、即拷即用。行业从"应用商店"路线转向"开放文件"路线，正是 2025 年 Agent Skills 被广泛接受的原因。
4. **使用边界与失效条件**：技能不能突破模型的底层能力上限——模型不具备 Java 能力时，一份 Java 技能包也教不会它写好 Java，技能是"组织能力"而非"注入能力"；技能的实际效果取决于两个设计质量——触发描述不准（永不加载）与正文指令含糊（执行走样）；技能数量增长后依赖渐进披露控制成本，无节制堆叠会挤占上下文窗口。
