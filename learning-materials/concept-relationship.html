三、上下文如何影响 Agent 运行

上下文是 Agent 的"即时信息源"——它的每一步决策（思考、调什么工具、下一步做什么）都只基于当前上下文里看得见的内容。上下文怎么构成，Agent 就怎么"看世界"。

1. 上下文构成直接决定 Agent 的能力边界

  • 没有 Skill 时：上下文里只有系统提示+历史+用户输入，Agent 只能靠通用能力摸索，行为不稳定。
  • 加载 Skill 后：SKILL.md 的指令（触发条件、工作流、质量底线）被注入上下文，Agent 就"看见"了"该怎么做这件事"，行为变得稳定、一致。

2. 上下文容量限制 → 影响记忆与连贯性

  • Agent 在多步任务中要把中间结果、工具返回、历史思考都放进上下文。窗口满了，最早的信息被挤出，Agent 就"忘记"前面做过什么，可能重复动作或偏离目标。
  • 这也是为什么长任务要配合外部记忆/检索，把不急需的内容移出上下文、按需召回。
关键结论：上下文是 Agent 与外界唯一的"信息接口"——放进上下文的东西，Agent 才能用；放不进去的，Agent 就"看不见"。所以"怎么组织上下文"（放什么、按什么顺序、留多少）直接决定 Agent 表现。

四、Skill 如何沉淀可复用任务知识

Skill 把"怎么做好一类任务"的经验从人脑/零散提示词里抽出来，固化为可加载、可复用、可迭代的资产。它让经验不再"用完即丢"，而是沉淀下来供以后和他人复用。

沉淀的三个层次

层次沉淀了什么带来的价值
①指令沉淀把"做这类任务的步骤、规范、质量底线"写成 SKILL.md不用每次重述，加载即得一致产出
②工具沉淀把配套的工具/脚本和 Skill 绑定Agent 不仅知道"怎么做"，还自带"用什么做"
③经验回写成功执行流程可固化为新 Skill（Voyager 式技能库）Agent 越用越强，能力持续累积
关键结论：Skill 是"经验 → 资产"的转化器。一次写好，多次复用；团队共享，人人得到一致的高质量产出。这与"一次性提示词"的根本区别，就在于可沉淀、可复用、可迭代。

可以看到：Agent 是执行者，Context 是它每一步的信息来源与载体，Skill 是随时可注入的可复用知识。三者缺一，智能体就退化——没有 Agent 只是死脚本，没有上下文 Agent 看不见任何信息，没有 Skill 则每次都得从零摸索、无法复用经验。
