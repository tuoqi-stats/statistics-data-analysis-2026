> 🎯 **本章目标**：让你从"写一坨流水账代码"升级到"会拆解、会复用、会组织代码"。

## 一、为什么学函数？

先看一个生活化的类比：

| 现实世界 | Python 世界 |
| --- | --- |
| 料理机 | 函数 `def` |
| 放进料理机的食材 | 参数 `参数` |
| 按键选择"榨汁 / 绞肉" | 调用方式（位置参数 / 关键字参数） |
| 倒出来的成品果汁 | 返回值 `return` |
| 料理机内部的刀片，外面看不见 | 局部作用域 |
| 一台机器做几百杯果汁 | 代码复用 |

**没有函数的代码**：复制粘贴 → 改一处忘另一处 → 越来越长 → 无法维护。
**有函数的代码**：一个功能只写一次 → 到处调用 → 长度可控 → 改一处全生效。

## 四、学习重点

1. **函数的三段式思维**
   输入（参数）→ 处理（函数体）→ 输出（返回值）。
   写函数前先想清楚：我需要什么数据？我要算出什么？中间步骤是什么？

2. **一个函数只干一件事**
   `get_user_age()` 就只负责拿年龄，不要在里面对数据库、发邮件、打印日志全干了。
   函数越小越短，越容易测试和复用。

3. **命名要"动词 + 名词"**
   `calculate_total()`、`is_valid_email()`、`find_max_value()` —— 看到名字就知道干什么。

4. **参数设计决定函数的易用性**
   - 必需的放前面，可选的给默认值放后面
   - 调用点清晰比函数体简短更重要，`send_email(to="a@b.com")` 比 `send_email("a@b.com", True)` 可读得多

5. **理解「返回值」与「副作用」的区别**
   - 返回值：`return total` —— 函数把结果交给你，你决定怎么用
   - 副作用：`print(total)` —— 函数自己把东西输出掉了
   - 💡 好的函数以返回值为主要产出，`print` 尽量留在最外层（这也是为什么本教程的示例里大多是 `print(函数())` 的写法）

6. **作用域是"变量的可见范围"**
   记住 LEGB：Local → Enclosing → Global → Built-in，逐层往外找，找不到就报 `NameError`。

## 五、常见误区 ⚠️

| # | 误区 | 说明 | 对应文件 |
| --- | --- | --- | --- |
| 1 | **函数定义后不会自动执行** | `def` 只是"登记"了一个功能，必须 `函数名()` 才叫调用 | 01 |
| 2 | **忘记写 `return`** | 没写 `return` 时函数返回 `None`，不是返回 `0` 或空字符串 | 04 |
| 3 | **默认参数用可变对象** ⚠️⚠️ | `def f(x, lst=[])` 的 `[]` **只创建一次**，多次调用会累积脏数据！必须用 `lst=None` 再判断 | 02 |
| 4 | **位置参数和关键字参数顺序错** | `f(a=1, 2)` 是语法错误；必须"先位置、后关键字" | 02 |
| 5 | **`*args` 和 `**kwargs` 搞混** | `*` 收集成**元组**（按位置），`**` 收集成**字典**（按名字） | 03 |
| 6 | **在函数内直接修改全局变量** | 不加 `global` 时，函数内赋值会创建新的局部变量，外面的值纹丝不动 | 05 |
| 7 | **滥用 `global` / `nonlocal`** | 让数据流向变得不可追踪，是 bug 温床。能用参数传入 + 返回传出就绝不用 `global` | 05 |
| 8 | **递归忘记写终止条件** | 没有 `if` 出口就会无限递归，最终 `RecursionError: maximum recursion depth exceeded` | 06 |
| 9 | **把 `f` 和 `f()` 混为一谈** | `f` 是函数对象本身（可以赋值、传递），`f()` 是调用它拿到结果 | 07 |
| 10 | **lambda 里写复杂逻辑** | `lambda` 只适合"一行能写完的小函数"，复杂的还是用 `def` | 07 |
